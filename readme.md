# AntiAd Telegram Bot

Бот для модерации групп и комментариев к Telegram-каналам на Python и aiogram 3.
Проверяет новые и отредактированные сообщения обычных участников.
Владелец, администраторы и анонимные администраторы группы исключены из модерации.
Автоматические публикации связанного канала в группе обсуждений сохраняются.

## Что удаляется

- Любые ссылки, включая ссылки без `https://`, скрытые ссылки в тексте и подписях,
  кнопки со ссылками, `@username`, упоминания пользователей и адреса электронной почты.
- Распространённые маскировки: `t[.]me`, `t(dot)me`, `t me`, Unicode-точки и невидимые символы.
- Фото, видео, документы, GIF, видеокружки, аудио, голосовые сообщения, стикеры,
  платные медиа и Live Photo. Каждый элемент альбома проверяется отдельно.
- Вложения, ссылки и реклама внутри Rich Messages также проверяются.
- Реклама без ссылок: призывы подписаться, предложения услуг или заработка с обращением
  в личку, сочетания коммерческих слов с большим количеством капса или эмодзи.
- Повторы: начиная с третьего одинакового сообщения за 60 секунд от одного участника.
- Флуд: начиная с шестого сообщения за 10 секунд от одного участника.
- Сообщения от имени сторонних каналов, если `DELETE_CHANNEL_MESSAGES=true`.

Ссылки и вложения удаляются независимо от рекламного порога. Реклама без ссылок
определяется по правилам, поэтому возможны пропуски и ложные срабатывания.
Обычные слова «канал», «чат», «группа» сами по себе не считаются рекламой.
Бот анализирует само сообщение, а не текст сообщения, на которое ответил участник.

Telegram не сообщает личность человека, написавшего от имени стороннего канала,
поэтому проверить его права в группе нельзя. Исключение для анонимных администраторов
относится к сообщениям от имени самой группы.

## Подготовка Telegram

1. Добавьте бота **в группу обсуждений**, где участники оставляют комментарии.
   Добавления только в канал недостаточно.
2. Назначьте бота администратором и включите право **«Удаление сообщений»**.
3. Для `TARGET_CHAT_ID` используйте ID группы, а не канала. Значение можно оставить
   пустым, чтобы бот работал во всех группах, куда его добавили.

Администратор-бот получает сообщения группы независимо от Privacy Mode.
Основание: [Telegram FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).
Права и ограничения удаления описаны в [Bot API](https://core.telegram.org/bots/api#deletemessage).

## Запуск

Нужен Python 3.10 или новее. Из каталога проекта:

```bash
python -m venv .venv
```

Активируйте окружение:

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

```bash
# Linux / macOS
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

При первом запуске создайте `.env` по образцу `.env.example`, укажите `BOT_TOKEN`
и при необходимости `TARGET_CHAT_ID`. Существующий `.env` с токеном сохраняйте.
Запустите один экземпляр бота:

```bash
python main.py
```

При заданном `TARGET_CHAT_ID` бот проверит доступ к группе и право удаления перед
запуском. Изменения собственных прав бот отслеживает через `my_chat_member` и пишет
в журнал `BOT READY` или `BOT NOT READY`. При переходе с webhook на polling webhook
снимается с сохранением ожидающих обновлений.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Токен из BotFather, обязателен |
| `TARGET_CHAT_ID` | пусто | ID конкретной группы |
| `DELETE_CHANNEL_MESSAGES` | `true` | Удаление любых сообщений от сторонних каналов |
| `AD_SCORE_THRESHOLD` | `2` | Порог рекламы без ссылок; ссылки и медиа запрещены всегда |
| `SPAM_REPEAT_LIMIT` | `3` | С какого одинакового сообщения начинается удаление |
| `SPAM_REPEAT_WINDOW` | `60` | Окно повторов в секундах |
| `SPAM_FLOOD_LIMIT` | `6` | С какого сообщения начинается удаление флуда |
| `SPAM_FLOOD_WINDOW` | `10` | Окно флуда в секундах |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

Лимиты сообщений задаются от 1 до 100, окна и рекламный порог — положительными числами.
Старая настройка `TEST_MODE_DELETE_ADMINS=true` игнорируется с предупреждением:
администраторы всегда исключены из модерации.

Если в старом `.env` осталось `DELETE_CHANNEL_MESSAGES=false`, сообщения сторонних
каналов всё равно проверяются на ссылки, медиа и рекламу, но обычный текст разрешён.

Счётчики повторов и флуда хранятся в памяти отдельно для каждой пары «группа — участник»
и сбрасываются при перезапуске. Удаляется текущее сообщение, достигшее лимита, и
последующие сообщения, пока лимит превышен. Предыдущие сообщения задним числом не удаляются.

## Если сообщения не удаляются

- Проверяйте с обычного аккаунта: сообщения администраторов сохраняются намеренно.
- Проверьте группу, `TARGET_CHAT_ID`, права бота и что запущен обновлённый код.
- `ADMIN CHECK FAILED` означает, что Telegram не позволил проверить статус автора.
  Такое сообщение пропускается, чтобы не удалить сообщение администратора по ошибке.
- `DELETE FAILED` / `DELETE FORBIDDEN` указывают на ошибку Telegram или недостаточные права.
  `DELETE SUCCESS` появляется только после успешного удаления.
- При коротком ограничении частоты или сетевой ошибке удаления выполняется до трёх попыток.
- Telegram обычно разрешает удалять сообщения младше 48 часов. Бот не сканирует историю.

В журнал записываются ID сообщений, причины и результат удаления; содержимое сообщений
и токен не записываются. Старый `moderation_log.txt` больше не пополняется.

## Проверки

Тесты работают без токена и сети, используя подмену Telegram API:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
```

Покрываются обработка новых сообщений и правок, исключения для администраторов,
скрытые ссылки, вложения, повторы, флуд, права бота и ошибки Telegram.
